Recipes · SFT + preference tuning

SFT warm start, then on-policy DPO, against hallucination

Take a 9B model that invents an answer for 98% of made-up names. Fine-tune it on honest answers for 12 minutes, then run a short DPO round on its own mistakes. Fabrication falls to 2%.

From OpenEuroLLMRecipe by Birger MoellRun once by its author. Not yet reproduced by anyone else.

1Ingredients

Two training sets, both published row for row. The first teaches the behaviour with supervised fine-tuning. The second corrects it with preference pairs built from the warm-started model's own answers.

3Equipment

Both training stages ran on 2 nodes with 4 A100 64 GB GPUs each (Leonardo, CINECA). The SFT stage took 12 minutes. The DPO stage is 15 optimizer steps. Building the pairs needs one more node with 2 GPUs, for sampling and for the judge.

4Method

Paths in angle brackets are yours to fill in. Account IDs and personal paths have been removed.

  1. 1

    Get the code and the data

    The dataset holds the exact training rows for both stages, so you do not need to rebuild them.

    git clone https://github.com/BirgerMoell/oellm-hallucination
hf download birgermoell/prelude-9b-sft-v2-hallucination-r2-data --repo-type dataset \
  --revision ebf8f1e1220e65cbbfad0926dcace237e1897385 --local-dir <DATA>
  2. 2

    Get the base model

    Download the base model at the revision the run started from.

    hf download marianna13/prelude-9b-sft-v2 \
  --revision 8670e89bb59dd491480a5c980179eed3083af9f3 --local-dir <MODELS>/prelude-9b-sft-v2
  3. 3

    Tokenize the SFT set

    Each assistant turn becomes one example: the generation prompt as the model sees it in default mode, then the reply and the end-of-turn token. Only the reply is supervised.

    python oellm-hallucination/train/pretok_sft.py --rows <DATA>/sft-warmstart \
  --tokenizer <MODELS>/prelude-9b-sft-v2 --out <WORK>/warmstart/pretok
  4. 4

    Train the warm start

    Supervised fine-tuning on the tokenized set. Use your own trainer with these settings.

    # assistant-only loss · 2 epochs · learning rate 5e-6 · packed to 16K tokens
# 2 nodes x 4 A100 64 GB · about 12 minutes
# save the result as <MODELS>/warmstart

    Check this. The launch script and trainer config for this stage are not published. The settings above are from the model card.

  5. 5

    Check before going on

    Run the benchmark on the warm-started model (step 8). Fabrication should already be near 4%. Expect it to decline about a quarter of the questions about well-known people. The next stage is meant to correct that.

    # original run after this stage: fabrication 3.6%, good "I don't know" 96.4%,
# abstains on 27.5% of well-known people, 98.2% of answers in the right language
  6. 6

    Tokenize the DPO pairs

    Tokenize the released round-2 mix with the model's own chat template. Concat mode builds each answer the way the model produces it at inference.

    python oellm-hallucination/train/pretok_pairs.py --staged <DATA>/round2-dpo/mix \
  --tokenizer <MODELS>/warmstart --out <WORK>/dpo-r2/pretok --mode concat

    Check this. The files hold 1,918 training pairs and the model card reports 1,896. The script drops pairs over 2,048 tokens, which would explain the difference. Compare with the manifest.json it writes.

  7. 7

    Train DPO round 2

    One short epoch of DPO on the warm-started model, with an SFT term on the preferred answer.

    # TRL DPO · loss_type [sigmoid, sft], weights 1.0 / 0.5 · beta 0.1
# learning rate 3e-6, cosine, 10% warmup · 1 epoch (15 steps) · global batch 128
# max length 2,048 · bf16 · FSDP · 2 nodes x 4 A100 64 GB

    Check this. The launch script and trainer config for this stage are not published either.

  8. 8

    Run the benchmark

    500 questions in default and thinking mode, graded by gemma-4-31B-it. One node with 2 GPUs.

    MODELS="base=<MODELS>/prelude-9b-sft-v2 r2=<MODELS>/dpo-r2" \
JUDGE=<MODELS>/gemma-4-31B-it PYTHON=<python with vLLM 0.24 or later> \
  sbatch --account=<your-project> --partition=<gpu partition> --export=ALL \
  oellm-hallucination/benchmark/run_slurm.sbatch
Optional: the job that rebuilds the pairs (sample, judge, curate, pair, audit)
#!/bin/bash
#SBATCH --job-name=halu-pairs
#SBATCH --nodes=1
#SBATCH --ntasks=1
#SBATCH --gpus-per-node=2
#SBATCH --cpus-per-task=16
#SBATCH --mem=200G
#SBATCH --time=10:00:00
#SBATCH --output=halu-pairs-%j.out
# On-policy DPO data on one node with 2 GPUs: sample the policy (one shard per GPU), judge every sample (2 GPUs),
# check the chosen candidates and write the missing ones (2 GPUs), build the pairs. Each step is skipped when its output exists, so
# a resubmitted job continues. Everything site-specific comes from the environment:
#
#   POLICY=/path/to/model           the model to be trained
#   POOL=data/train/pool.jsonl      questions (train/build_pool.py)
#   JUDGE=/path/to/gemma-4-31B-it   judge and writer
#   PYTHON=/path/to/python          an environment with vLLM (>= 0.24 for Gemma 4) and transformers
#   CONTAINER=/path/to/image.sif    optional: run python inside this Apptainer/Singularity image
#   BINDS=/a,/b                     optional: container bind paths (default: the working dir, judge and policy dirs)
#   OUT=runs/<name>                 output directory;  K=8 samples per question
#   KNOWN_SHARE=0.35                minimum share of answer pairs (known + sharpen) among the hallucination pairs
#   AUDIT_JUDGE=/path/to/Qwen3.5-27B optional: audit the pairs (audit_pairs.py) with a second judge from another family
#
#   sbatch --account=<account> --partition=<gpu partition> --export=ALL train/run_slurm.sbatch
set -euo pipefail
: "${POLICY:?}" "${POOL:?}" "${JUDGE:?}" "${PYTHON:?}" "${OUT:?}"
K=${K:-8}
HERE=$(cd "$(dirname "$0")" && pwd)
[[ -f "$HERE/sample.py" ]] || HERE=$SLURM_SUBMIT_DIR/train
BENCH=$HERE/../benchmark
py() {
  if [[ -n ${CONTAINER:-} ]]; then
    $(command -v apptainer || command -v singularity) exec --nv \
      -B "${BINDS:-$PWD,$(dirname "$JUDGE"),$(dirname "$POLICY")}" "$CONTAINER" \
      env HF_HUB_OFFLINE=1 VLLM_NO_USAGE_STATS=1 "$PYTHON" "$@"
  else
    HF_HUB_OFFLINE=1 VLLM_NO_USAGE_STATS=1 "$PYTHON" "$@"
  fi
}
mkdir -p "$OUT"
if [[ ! -s $OUT/samples.jsonl ]]; then
  echo "== sample $(date)"
  for g in 0 1; do
    CUDA_VISIBLE_DEVICES=$g py "$HERE/sample.py" --pool "$POOL" --model "$POLICY" --k "$K" --shard "$g/2" \
      --out "$OUT/samples-$g.jsonl" &
  done
  wait
  cat "$OUT/samples-0.jsonl" "$OUT/samples-1.jsonl" > "$OUT/samples.jsonl"
fi
if [[ ! -s $OUT/judged.jsonl ]]; then
  echo "== judge $(date)"
  py "$BENCH/judge.py" --answers "$OUT/samples.jsonl" --judge "$JUDGE" --tp 2 --out "$OUT/judged.jsonl"
fi
if [[ ! -s $OUT/curated.jsonl ]]; then
  echo "== curate $(date)"
  py "$HERE/build_pairs.py" curate --judged "$OUT/judged.jsonl" --writer "$JUDGE" --tp 2 --out "$OUT/curated.jsonl"
fi
echo "== pairs $(date)"
py "$HERE/build_pairs.py" pairs --judged "$OUT/judged.jsonl" --curated "$OUT/curated.jsonl" --out-dir "$OUT/pairs" \
  --known-share "${KNOWN_SHARE:-0.35}"
if [[ -n ${AUDIT_JUDGE:-} ]]; then
  echo "== audit $(date)"
  py "$HERE/audit_pairs.py" checks --pairs "$OUT/pairs" --pool "$POOL"
  py "$HERE/audit_pairs.py" judge --pairs "$OUT/pairs" --pool "$POOL" --judge "$AUDIT_JUDGE" --tp 2 --per-cell "${AUDIT_PER_CELL:-30}"
fi
echo "== done $(date)"

7Known gaps

What stands between this card and an exact copy of the run.

  • The launch scripts and trainer configs for the two training stages are not published. Their settings come from the model card.
  • Library versions and seeds for the training stages are not stated. The wall time of the DPO stage is not stated either.
  • Rebuilding the pairs gives similar, not identical, data: sampling and the LLM judge are stochastic. Use the released files for a faithful rerun.
  • The general preference pairs were sampled from a staged set on the original cluster. The sampled rows are published, the staged set is not.
  • The scripts take every site-specific value from environment variables. You supply the account, partition, Python environment and model paths.
  • Only the hallucination benchmark has been run on the result. Maths, code, tool use and long context were not measured.
  • No licence is stated for the base model. The checkpoint is shared on the same terms.
