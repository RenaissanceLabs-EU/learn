Recipes · Preference tuning

Full-weight DPO on 1.4 million preference pairs

Take a supervised fine-tuned 9B model and tune it on pairs of preferred and rejected answers. One epoch, every weight updated, 32 GPUs, under two days.

From OpenEuroLLMRecipe by Birger MoellRun once by its author. Not yet reproduced by anyone else.

4Method

Paths in angle brackets are yours to fill in. Account IDs and personal paths have been removed.

  1. 1

    Get the code

    Check out the exact training code.

    git clone https://github.com/BirgerMoell/post-training
cd post-training
git checkout 64f3599
  2. 2

    Prepare the base model

    Download the base model at the pinned revision. Then fix its tokenizer. The run used a repaired tokenizer configuration, and loading the original may not reproduce the training startup. Use the two files from the release.

    hf download Neonkraft/oellm-9b-256k-theta64m-prelude-anneal300b-instruct-sft \
  --revision 85bf18fb4f0bee6ac6270f06b1d1c6b3be200f31 --local-dir <SCRATCH>/artifacts/model
hf download birgermoell/oellm-9b-threeway-dpo-full-v1 \
  base_tokenizer_config_used.json tokenizer.model --local-dir ./release-files

    Check this. Confirm exactly how the two release files replace the base model's tokenizer files.

  3. 3

    Stage the data

    The staging script builds the six training and validation files. It reads HelpSteer3 from files you must prepare first (preference-train.jsonl.gz and preference-validation.jsonl.gz), and it does not download them. Set the two path constants at the top of the script, then run it and check the fingerprints.

    python stage_threeway_dpo_full.py
cd <WORK>/artifacts/data/threeway-full
sha256sum -c data_checksums.sha256

    Check this. HelpSteer3 and UltraFeedback were not revision-pinned, so the checksums only match if the sources have not changed.

  4. 4

    Set the paths

    Copy the frozen config from the release. Change the model path and the six data paths to your own.

    cp training_config.yaml <WORK>/configs/oellm-9b-threeway-dpo-full-lumi.yaml
  5. 5

    Launch

    Submit from the checked-out training repository. The script uses its src folder, scripts/train.py and configs/accelerate/fsdp_lumi.yaml.

    sbatch training_slurm.sbatch
The launch script, with placeholders
#!/bin/bash
#SBATCH --job-name=oellm-3way-dpo-full
#SBATCH --account=<your-project>
#SBATCH --partition=small-g
#SBATCH --nodes=4
#SBATCH --gpus-per-node=8
#SBATCH --ntasks-per-node=1
#SBATCH --cpus-per-task=56
#SBATCH --mem=480G
#SBATCH --time=2-00:00:00
#SBATCH --signal=B:USR1@300
#SBATCH --output=<WORK>/logs/%j.out
#SBATCH --error=<WORK>/logs/%j.err

set -euo pipefail
module purge

GPUS_PER_NODE=8
TRAIN_CONFIG=<WORK>/configs/oellm-9b-threeway-dpo-full-lumi.yaml
CONTAINER=<SCRATCH>/containers/laif-rocm-6.4.4-pytorch-2.9.1-te-2.4.0-fa-2.8.0-triton-3.2.0.sif
OVERLAY=<SCRATCH>/pylibs-overlay
BIND=/pfs,/scratch,/flash,/project,/projappl,/appl,/opt/cray,/var/spool/slurmd
HF_CACHE=<WORK>/artifacts/cache/huggingface

mkdir -p "$HF_CACHE" <WORK>/outputs
export MASTER_ADDR=$(scontrol show hostnames "$SLURM_JOB_NODELIST" | head -n 1)
export MASTER_PORT=$(python3 -c "import socket; s=socket.socket(); s.bind(('', 0)); print(s.getsockname()[1]); s.close()")
export NCCL_SOCKET_IFNAME=hsn0,hsn1,hsn2,hsn3 NCCL_NET_GDR_LEVEL=PHB FI_CXI_DEFAULT_CQ_SIZE=131072
export TORCH_NCCL_TRACE_BUFFER_SIZE=1048576 TORCH_NCCL_DUMP_ON_TIMEOUT=1 TORCH_NCCL_DESYNC_DEBUG=1
export OMP_NUM_THREADS=7 PYTORCH_HIP_ALLOC_CONF=expandable_segments:True PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True
WORLD_SIZE=$(( GPUS_PER_NODE * SLURM_NNODES ))

echo "Full three-way DPO: config=$TRAIN_CONFIG nodes=$SLURM_NNODES world=$WORLD_SIZE"
srun --label --export=ALL --wait=60 --kill-on-bad-exit=1 singularity exec -B "$BIND" "$CONTAINER" bash -lc "
  set -euo pipefail
  export PYTHONPATH=$OVERLAY:$SLURM_SUBMIT_DIR/src:\${PYTHONPATH:-}
  export HF_HOME=$HF_CACHE HF_HUB_CACHE=$HF_CACHE/hub HUGGINGFACE_HUB_CACHE=$HF_CACHE/hub HF_DATASETS_CACHE=$HF_CACHE/datasets
  export HF_HUB_OFFLINE=1 HF_DATASETS_OFFLINE=1 TRANSFORMERS_OFFLINE=1 HF_HUB_DISABLE_TELEMETRY=1 WANDB_MODE=disabled
  export ACCELERATE_USE_FSDP=true FSDP_CPU_RAM_EFFICIENT_LOADING=1
  cd $SLURM_SUBMIT_DIR
  accelerate launch \
    --config_file configs/accelerate/fsdp_lumi.yaml \
    --num_machines $SLURM_NNODES \
    --num_processes $WORLD_SIZE \
    --machine_rank \$SLURM_PROCID \
    --main_process_ip '$MASTER_ADDR' \
    --main_process_port '$MASTER_PORT' \
    scripts/train.py --config $TRAIN_CONFIG accelerate.use_deepspeed=false deepspeed=null
"

7Known gaps

What stands between this card and an exact copy of the run.

  • The staged data files are not published. Only their SHA-256 fingerprints are, and they sit on the original cluster.
  • HelpSteer3 and UltraFeedback were not revision-pinned, so restaging can produce different bytes.
  • The staging script does not fetch HelpSteer3. It expects two files you prepare first.
  • The base model's tokenizer configuration was repaired before training. The fix is released, and the exact way to apply it needs confirming.
  • Only model weights were saved, so the original optimizer trajectory cannot be resumed.
  • The scripts are written for LUMI (AMD GPUs, Singularity, Cray network settings). Other clusters need changes to the container, the network variables and the paths.
  • Account IDs and personal paths were removed from this page. Replace the <placeholders>.
